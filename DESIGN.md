# Дизайн-документ MVP

## 1. Концепция

Личное Android-приложение-хаб **Lumo Hub** для доступа к собственным сервисам: AI-чат сейчас,
«Умные грядки» и другие модули позже. Приложение не является публичной
социальной платформой: приоритеты — быстрый доступ, спокойный интерфейс,
локальность данных и простая настройка собственного API-провайдера.

Рабочее визуальное направление — **Lumo-inspired**, без копирования бренда:
воздушный premium-интерфейс, мягкие градиенты, крупная типографика, округлые
карточки и спокойные пастельные акценты.

Переданный UI-референс уточняет композицию: верхняя компактная панель с меню,
центральное приветствие и абстрактный светящийся orb, ряд быстрых действий,
composer внизу контента и нижняя навигация. Экран сервисов использует заголовок,
сетку инструментов, список недавних чатов и выделенную карточку профиля/плана.

## 2. Цели MVP

- Открывать все доступные функции с одного Dashboard.
- Запускать AI-чат с OpenAI-compatible провайдером.
- Поддерживать историю диалогов.
- Показывать ответ модели потоково (streaming).
- Настраивать один API-профиль: Base URL, API key, model.
- Работать в светлой и тёмной системных темах.
- Не требовать собственного backend и аккаунта.
- Работать на русском языке в MVP.
- Открывать Dashboard сразу при первом запуске, без обязательного onboarding.

## 3. Не входит в MVP

- Синхронизация между устройствами.
- Собственный сервер, регистрация и облачная авторизация.
- Несколько профилей провайдеров.
- Реализация «Умных грядок» — только заглушка модуля.
- Голосовой ввод, файлы, изображения и web search.
- Сложная система разрешений и ролей.

## 4. Информационная архитектура

Нижняя навигация из трёх разделов:

1. **Главная** — обзор сервисов и быстрый запуск.
2. **Чат** — список диалогов и переход в разговор.
3. **Настройки** — провайдер, тема и локальные параметры.

### Dashboard

- Верхняя панель: иконка приложения, название/логотип, кнопка настроек.
- Приветствие: «Добрый день» или «Добрый вечер».
- Подзаголовок: «Что будем делать?».
- Центральный декоративный orb — главный визуальный фокус, без обязательной
  функциональной нагрузки.
- Основная карточка AI Chat: короткое описание и CTA «Новый чат».
- Сетка сервисов:
  - AI Chat — активный модуль;
  - Умные грядки — «Скоро»;
  - будущие модули — «Скоро».
- Блок «Недавние чаты» с последними диалогами.
- Нижняя навигация.

### Chat list

- Заголовок «Чаты».
- Кнопка создания нового диалога.
- Поиск или фильтр можно отложить до следующей версии.
- Список: название, превью последнего сообщения, время.
- Empty state с CTA «Начать новый чат».
- При создании чата можно задать его цель или системную роль.
- Отдельный чат можно удалить через меню с подтверждением.
- Роль можно добавить или изменить уже внутри открытого чата.
- Название нового чата формируется по первому сообщению.

### Conversation

- Верхняя панель: назад, название чата, меню.
- Сообщения пользователя и ассистента с визуально разными блоками.
- Streaming-ответ постепенно дополняется в последнем bubble.
- Состояния: отправка, ошибка, повторить, остановить генерацию.
- Нижняя composer-панель: многострочный ввод, отправка, остановка ответа.
- При остановке уже полученный частичный ответ сохраняется в истории.
- Выбор модели в MVP — в настройках, не в каждом сообщении.
- Роль текущего чата отображается компактно в шапке.
- Список моделей загружается через API провайдера и должен отражать модели,
  доступные именно текущему API key; ручной ввод остаётся запасным вариантом.
- Ответы отображаются с Markdown-форматированием и копированием сообщения.

### Settings

- Раздел «AI-провайдер».
- Поля: Base URL, API key, Model.
- Начальные подсказки формы: `https://api.openai.com/v1` и пример модели OpenAI.
- API key маскируется; показать/скрыть — явное действие.
- CTA «Проверить подключение» и «Сохранить».
- Сохранение блокируется, если список доступных моделей не удалось получить.
- Удаление чата выполняется через стандартный диалог подтверждения.
- Сохранение блокируется, если список доступных моделей не удалось получить.
- Раздел «Внешний вид»: системная тема / светлая / тёмная.
- Раздел «Данные»: очистить историю с подтверждением.
- Модуль «Умные грядки» открывает экран-заглушку со статусом «Скоро».
- При открытии будущего модуля показывается экран-заглушка «Скоро».

## 5. Визуальная система

### Принципы

- Много свободного пространства, контент не перегружен.
- Карточки с радиусом 20–28 dp.
- Основные CTA — заметные, но не кричащие.
- Иконки простые, линейные, с одним акцентным цветом.
- Анимации короткие и функциональные: появление карточек, streaming,
  переходы навигации.

### Цвет

Светлая тема — тёплый почти белый фон, графитовый текст, голубой/лавандовый
акцент, мягкий персиковый secondary accent. Тёмная тема — глубокий графитовый
фон, не чистый чёрный, с теми же акцентами в менее контрастной насыщенности.

Точные значения цветов будут вынесены в Compose theme после первого визуального
прототипа и проверены на контрастность.

### Типографика

- Display: крупное приветствие на Dashboard.
- Title: заголовки экранов и карточек.
- Body: описания и сообщения.
- Label: кнопки, статусы и время.

Использовать системный шрифт Android, чтобы не добавлять тяжёлые зависимости.

## 6. Поведение AI-чата

Запрос отправляется на:

```text
POST {baseUrl}/chat/completions
Authorization: Bearer {apiKey}
Content-Type: application/json
```

Для streaming используется `stream: true` и SSE-совместимое чтение `data:`
событий. Клиент должен корректно обработать `[DONE]`, частичные chunks,
сетевой timeout, HTTP 401/403, 404, 429 и отсутствие подключения.

История MVP хранится локально на устройстве. API key хранится отдельно в
Android Keystore-backed storage; в обычную базу сообщений ключ не попадает.

## 7. Техническая основа

- Kotlin.
- Jetpack Compose + Material 3.
- Single-activity приложение.
- Navigation Compose.
- ViewModel + StateFlow.
- Coroutines.
- Room для локальной истории чатов.
- HTTP-клиент с поддержкой streaming.
- Android Keystore для API key.

## 8. Критерии готовности MVP

- Приложение запускается на эмуляторе и физическом Android-устройстве.
- Dashboard открывает активный Chat и показывает будущие сервисы.
- Провайдер сохраняется, соединение проверяется.
- Можно создать, закрыть и снова открыть чат после перезапуска приложения.
- Ответ ассистента отображается потоково.
- Ошибка сети/авторизации понятна пользователю и не теряет черновик.
- Светлая и тёмная темы не ломают контраст и навигацию.
- Debug APK собирается через Gradle.

## 9. Этапы реализации

1. Scaffold, тема, навигация и Dashboard.
2. Settings с локальным профилем и безопасным API key.
3. Room-модель истории и список чатов.
4. Conversation UI и обычный запрос.
5. Streaming SSE, отмена, retry и ошибки.
6. Визуальная полировка, accessibility и проверка APK.

В MVP отдельный accessibility-аудит не проводится; его добавим после визуального
прототипа.
